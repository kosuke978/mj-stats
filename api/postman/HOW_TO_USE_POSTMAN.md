# Postman を使った API テスト・ガイド

このドキュメントは、本プロジェクト（mj-stats）において、新しくAPIを作成した際に「**どのようにPostmanを使ってテストするか**」「**そもそも何のために何を確認しているのか**」をまとめた指標です。

---

## 1. そもそも Postman とは何なのか？

一言で言うと、**「フロントエンド（Reactやアプリの画面）の代役」** です。

通常、ユーザーが「対局結果を保存する」ボタンを押すと、画面（フロントエンド）からバックエンド（GoのAPI）に対してデータ（JSON）が送信されます。
しかし、開発中はまだ画面が完成していません。そこで、**画面の代わりにAPIを叩いて（リクエストを送って）くれるツール** が Postman です。

### 何を確認しているのか？（テストの目的）
APIテストでは、以下の3点が「設計通りに動くか」を確認しています。

1. **受け取り**: GoのAPIが、Postmanからのデータ（JSON）をエラーなく受け取れるか？
2. **処理・保存**: APIが受け取ったデータを元に、Supabase（DB）に正しくデータを保存・更新できるか？
3. **返却**: 成功したか、失敗したかを正しく Postman（将来のフロントエンド）に返せるか？（ステータスコード 200 や 201 など）

---

## 2. API開発とテストの基本ワークフロー

新しいAPI（例：成績一覧を取得する `GET /api/matches` など）を作った際の、基本的な手順は以下の通りです。

### Step 1: API (Go) のコードを書く
- ルーティング（`main.go` など）にパスを追加する。
- コントローラー（`match_controller.go` など）に処理を書く。
- **ポイント**: 最初は複雑な処理を書かず、「とりあえずリクエストを受け取って返すだけ」のシンプルな状態から始める。

### Step 2: テスト用データの準備（超重要！）
- **ここが一番のハマりポイントです。** 
- データベース（Supabase）が `UUID` を要求しているカラムに `"user_1"` のようなただの文字列を送ると必ずエラーになります。
- データの作成や更新を行うAPIの場合は、必ず **Supabase の Table Editor を見て、本物のID（UUID）をコピーして準備** してください。

### Step 3: APIサーバーを起動する
ターミナルを開き、APIディレクトリでサーバーを起動します。
```bash
cd api
go run .
```

### Step 4: Postman でリクエストを作成・送信する
1. Postman を開き、`+` ボタンから新しい Request を作成します。
2. HTTPメソッド（GET, POST, PUT, DELETE など）を選択します。
3. URLを入力します。（例: `http://localhost:8080/api/matches`）
4. （POST/PUTの場合）`Body` タブ -> `raw` -> `JSON` を選択し、送信するデータを書きます。
5. **Send** ボタンを押します。

### Step 5: 結果（レスポンス）を確認する
Postman の画面下部（Response）を確認します。

- 🟢 **200 OK / 201 Created**: 成功です！
  - データの作成（POST）をした場合は、**必ず Supabase の Table Editor も開いて、本当にデータが入っているか目視確認** してください。
- 🔴 **400 Bad Request**: 送信したJSONの形（形式）が間違っています。リクエストを見直します。
- 🔴 **500 Internal Server Error**: API側（Go）からDBへの書き込みなどでエラーが起きました。ターミナル（`go run .` の画面）のエラーログを見ます。

## 3. よくあるエラーと対処法（過去の教訓）

今回の開発で発生したようなエラーに遭遇した時のチェックリストです。

### Q1. `pq: invalid input syntax for type uuid: "xxx"` というエラーが出る
**原因**: Supabase はそのカラムを `uuid` 型（例: `123e4567-e89b-12d3...`）で設定しているのに、Postman から `"user_1"` や `"1"` のような違う形の文字列を送っています。
**対処**: Supabase の Management 画面（Table Editor）に行き、本物の UUID をコピーして JSON を書き換えてください。

### Q2. `pq: column "xxx" of relation "yyy" does not exist` というエラーが出る
**原因**: Goのコード内で書いたSQLのカラム名と、実際の Supabase 上のカラム名がズレています。
**対処**: Supabase の Table Editor で正確なカラム名を確認してください。（例: `point` ではなく `final_point` だった等）。それに合わせて Go 側の SQL (`INSERT INTO ...`) を修正します。

### Q3. `Connection refused` と Postman に表示される
**原因**: APIサーバーが動いていません。
**対処**: ターミナルで `go run .` を実行しているか確認してください。途中でクラッシュして止まっている場合もあります。

## 4. チーム開発（今後のため）の運用ルール

このフォルダ（`api/postman/`）には、正常に動作確認が取れた Postman の設定（Collection）をエクスポートして保存していきます。
API を追加・修正してテストが成功したら、Postman から JSON 形式でエクスポートし、Git にコミットしておくと、後から「どういうJSONを送れば成功するんだっけ？」と迷わなくなります。
